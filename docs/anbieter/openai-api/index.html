Zero Data Retentionbelegt
Ja, keine Speicherung der Anfragen
Nur auf Antrag, nicht Standard: „Currently, these controls are subject to prior approval by OpenAI and acceptance of additional requirements.“ Wirkung: „Zero Data Retention excludes customer content from abuse monitoring logs in the same way as Modified Abuse Monitoring.“ und der store-Parameter von Responses und Chat Completions wird als false behandelt. Nicht ZDR-fähig laut Tabelle u. a. /v1/conversations, /v1/assistants, /v1/threads, /v1/vector_stores, /v1/files, /v1/batches, /v1/fine_tuning/jobs, /v1/evals, /v1/agents: „Zero Data Retention ineligible endpoints or capabilities may retain application state when used, even if you have Zero Data Retention enabled.“ Ausnahme Bilder/Dateien: „If the classifier detects potential CSAM content, the image will be retained for manual review, even if Zero Data Retention, Modified Abuse Monitoring“ (oder weitere Schutzstufen) aktiv sind. OpenAI kann ZDR je Modell entziehen: „we reserve the right to make models ineligible for Zero Data Retention or Modified Abuse Monitoring for specific customers“ (mit schriftlicher Vorankündigung). Modified Abuse Monitoring (MAM) nimmt Inhalte aus den Missbrauchsprotokollen, lässt aber gespeicherte Anwendungsdaten zu: „Modified Abuse Monitoring excludes customer content (other than image and file inputs in rare cases, as described below ) from abuse monitoring logs across all API endpoints“. Speicherung ohne ZDR: „the Responses API has a 30 day Application State retention period by default, or when the store parameter is set to true .“ Assistants/Threads/Vector Stores: „Objects that are not deleted via the API or dashboard are retained indefinitely.“ Auch mit ZDR bleibt etwas liegen (Widerspruchs-Scan 23.10.2026, Werbung openai.com/api: „Zero data retention policy by request“): Zwischenspeicher „Prompt caching may store encrypted key/value tensors in GPU-local storage as application state. This data is stored on the local GPU machines and is not retained after the 24-hour expiration.“ (als Grenze bei Chat Completions, Responses und Decisions). Für GPT-5.6 und später (also die GPT-6-Modelle hier) nennt der Caching-Leitfaden nur „30m“ (Standard) und „12h“ als Mindestdauer, kein „in_memory“ und keine eigene ZDR-Regel; die ZDR-Voreinstellung „in_memory“ gilt nur für ältere Modelle. Ob ZDR-Kunden bei GPT-6 ohne Zwischenspeicher arbeiten können, ist ungeklärt. Hintergrund-Modus: „Response data is temporarily stored to disk for roughly 10 minutes to enable asynchronous execution and polling.“ (auch bei ZDR-Projekten).
