Zero Data Retentionbelegt
Ja, keine Speicherung der Anfragen
Erreichbar, aber nicht Standard; der Kunde muss mehrere Dinge selbst abschalten. Data-Governance-Seite (21.10.2026): „To achieve zero data retention, customers must take specific actions within each of these areas“. (1) Missbrauchs-Protokolle: „Only customers whose use of Google Cloud is governed by the Google Cloud Platform Terms of Service are subject to prompt logging for abuse monitoring.“ Kunden mit Rahmenvertrag: „customers with a Google Cloud Master Agreement are exempt from prompt logging for this abuse monitoring by default.“ Wie Kunden mit Online-AGB davon befreit werden, steht nicht in den Kopien (ungeklärt). (2) Zwischenspeicher: „By default, Google's published Gemini models cache Customer Data to reduce latency and accelerate responses.“ Er hält höchstens 24 Stunden („It's deleted no later than 24 hours after it's written“) und lässt sich je Projekt abschalten. (3) Grounding mit Google Search: „There is no way to disable the storage of this information if you use Grounding with Google Search.“ (4) Interactions API: „If you do not specify a value for store , it defaults to true for all models.“ Gemini Developer API zum Vergleich: „If your workload requires guaranteed zero data retention or enterprise data processing agreements, use Vertex AI.“ Nachtrag 23.10.2026 (Widerspruchs-Scan): Der Zwischenspeicher hat zwei Stufen, beide standardmäßig an. Läuft der Arbeitsspeicher voll, legt Google abgeleitete Daten auf Platte ab: „Google stores derived cache data (key-value representations computed from your inputs) in durable storage“, „It's stored at rest and encrypted with Google default encryption.“ und „Customer-managed encryption keys (CMEK) aren't supported for durable caching.“ Beim global-Endpunkt: „requests and their cached data can be served from any region.“ Die Plattenstufe lässt sich je Projekt einzeln abschalten.
