Pricing and rate limits

Table of contents

Use our models with pay-as-you-go billing on Meta Model API and in Muse Code, or in Muse Code with a monthly subscription. This page covers pay-as-you-go: Model API bills text models per token, image generation per image, Muse Voice Transcribe by the hour of audio processed, and Segment Anything Model (SAM) per image or video frame segmented, with no minimums or upfront commitment.

Pricing modes

Some models can be used in two modes. Standard mode uses standard pricing. Contributor mode offers discounted pricing or more usage in exchange for permission to use your content — the prompts, code, files, and context you send, plus the model responses you get back — to train future Meta models.

Standard mode

In Standard mode, you pay standard prices and your content is not used to train Meta models. Every model on this page is available in Standard mode.

Contributor mode

On Model API, Contributor mode runs the same models at heavily discounted token prices, in exchange for permission to use your content to train future Meta models. It lowers the barrier to entry for prototyping, testing integrations, and scaling experiments where it's acceptable for Meta to use your content to train future Meta models.

On Model API, use Contributor mode with Muse Spark 1.3 or 1.2 by calling its Contributor-mode variant: muse-spark-1.3-contributor or muse-spark-1.2-contributor. Contributor mode isn't available for Muse Wonder on Model API.

In Muse Code, subscriptions default to Contributor mode, and you can turn it on or off in settings; see Contributor mode in Muse Code.

Token pricing notes

These apply to the token-priced models above, Muse Wonder and Muse Spark.

Cached input costs less: When part of your prompt matches a cached prefix, you pay the cached-input rate for those tokens. Check cached_tokens in the response to see how many were served from cache.

No long-context premium: you pay the same rate whether your context window is mostly empty or almost full.

Web search grounding: $2.50 per 1,000 search queries, in addition to the request's token cost. This applies to the web_search tool on text models such as Muse Wonder and Muse Spark.

Muse Image search is included

Muse Image's built-in web and image search is part of its per-image price and isn't charged separately. See Muse Image pricing.

Muse Image

Usage

Price

Generated image

$0.01 per image

Muse Image is billed at a flat rate per generated image. The price is the same regardless of prompt length, reasoning_strength, or the tools the model uses during generation, including its built-in web and image search, which isn't charged separately. A request that returns n images is billed for n images. You're billed only for images the model successfully generates and returns: images that fail to generate, or that are removed by safety filtering before they're returned, aren't counted. Image responses still include a usage object with token counts for reference, but image generation tokens are not included in token-based pricing for other models. See the Image generation guide for the response shape.

Muse Voice Transcribe

Muse Voice Transcribe is billed by audio processed, metered in whole seconds.

Audio time is billed as a separate line item from token usage, rounded down to whole seconds; other endpoints aren't billed for audio time.

SAM 3.1 is billed per image or frame and Muse Image is priced per image, so neither has a TPM limit.

Muse Voice Transcribe is billed by audio processed, so it's limited by streams rather than requests or tokens. Concurrent streams caps how many transcription sessions you hold open at once; streams per hour caps how many you start. Realtime and file transcription share the same budget.

Token usage counts only your input and output tokens. Meta injects a small amount of steering context into every prompt (a system prompt and related scaffolding); those injected tokens are not billed and are excluded from the token counts reported in your usage and by the token-counting endpoints.

Background responses

Creating background responses (background: true) is limited to 600 submissions per minute, per team, in addition to the limits above. The cap applies only to starting new background responses: over it, new submissions return HTTP 429 Too Many Requests with a Retry-After header, and responses already running continue unaffected.

Handle rate limits

When you exceed a limit, the API rejects the request. Requests succeed again once usage drops below the limit.

Retry on 429 responses

Retry strategy: Use exponential backoff with jitter. Start with a short delay such as 500 ms, double it after each consecutive rate-limit response, and add random jitter so concurrent clients don't all retry at the same moment. If the response includes a Retry-After header, wait at least that long.

Read rate-limit headers

Every successful token-based response includes headers that report your current limit and remaining quota:

Header

Description

x-ratelimit-limit-tokens

Total token budget for the current window.

x-ratelimit-remaining-tokens

Tokens remaining before you hit the limit.

x-ratelimit-limit-requests

Total request budget for the current window.

x-ratelimit-remaining-requests

Requests remaining before you hit the limit.

Read these headers and slow down before you hit a rate limit instead of reacting after one.

Handle Muse Voice Transcribe rejections

A realtime stream rejected for exceeding a stream limit closes with 1013. A rejected file-transcription request returns HTTP 429 Too Many Requests. Transcription responses don't include the x-ratelimit-* headers.
